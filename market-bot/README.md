# Маркет-цены — Telegram-бот: цена товара на Яндекс Маркете раз в день

Личный бот. Раз в сутки открывает ваши ссылки на Яндекс Маркете и присылает цену в Telegram.

- 💰 **Цена после каждой проверки**: изменение к прошлому разу (📉 −23 ₽ / 📈 +40 ₽), зачёркнутая цена, продавец.
- 🎟 **Промокод** (по умолчанию на 5%): есть ли он сейчас на странице, код, потолок «до N ₽», **цена с промокодом**;
  сообщение, когда промокод появился или пропал. Минимум, цель и «когда дешевле» считаются по цене к оплате.
- 🔥 **Самая низкая цена за всё время**, 🎯 **цель** («сообщить, когда ≤ 1 100 ₽»), ⚠️ **смена продавца**, ❌/✅ **наличие**.
- 📈 **Динамика** (`/history`): график (цена и цена с промокодом), минимум, максимум, средняя за 7 и 30 дней,
  **в какой день недели обычно дешевле** и **когда чаще бывает промокод** (после 2 недель наблюдений), таблица CSV.
- 🕐 **Бережно к Маркету**: по умолчанию одна проверка в день (12:00 по Москве). Страница одного товара открывается
  **не больше 2 раз в сутки** — вместе с повтором после ошибки и ручными `/check`.
- Без внешних зависимостей: Node.js 22 (`node:sqlite`, встроенный `fetch`). Браузер (Playwright) — по желанию, против капчи.

## ⚠️ Что важно знать заранее

1. **Бот не проверялся на живой странице Маркета.** Из среды, где он писался, `market.yandex.ru` был недоступен.
   Цена берётся из данных, которые Маркет встраивает в страницу: JSON-LD и блоки `<noframes data-apiary="patch">`.
   Их устройство описано в открытом проекте [price_watcher](https://github.com/Dushe4ka/price_watcher), и на тестовой
   странице такого же устройства бот работает. Поэтому **первым делом запустите `npm run probe`** (шаг 5 ниже).
   Если цена не та или не нашлась, файл `data/debug/probe.json` покажет, что пришло, и по нему разбор легко поправить.
2. **История начинается с первой проверки.** Цен за прошлые дни бот взять неоткуда. Вывод «в какой день дешевле»
   появится через 2 недели, а надёжным станет через месяц-другой. При одной проверке в сутки бот видит одну цену в день,
   поэтому колебания внутри дня он не заметит.
3. **Капча.** Яндекс может показать серверу «Я не робот» вместо страницы. Как с этим справляться — в разделе
   [«Если Маркет показывает капчу»](#если-маркет-показывает-капчу).
4. **Промокод бот ищет на странице товара** — в её тексте («−5% по промокоду», «Промокод SALE5: 5% до 500 ₽»,
   «1 033 ₽ с промокодом») и в данных страницы. Как Маркет показывает промокоды в коде страницы, проверить было не на чем,
   поэтому после первой проверки сверьте с сайтом: строка «🎟 …» в сообщении должна совпадать с тем, что видно на карточке.
   Промокод, который появляется только в корзине или приходит в приложении, на странице товара не виден — его бот не заметит.
5. **Сверьте первую цену с сайтом.** Бот берёт основную цену предложения из ссылки (того продавца, которым вы поделились).
   Если на сайте вы видите другую цену (например, отдельную цену при оплате картой Яндекс Пэй или цену для другого
   региона доставки, ведь сервер в Нидерландах), пришлите вывод `/debug`.

## Установка одной командой

Нужны Node.js 22.13+ и токен бота от [@BotFather](https://t.me/BotFather). На сервере от root:

```bash
curl -fsSL https://raw.githubusercontent.com/gdima7249-cpu/3/claude/adoring-euler-f2cetx/market-bot/install.sh | bash -s -- ВАШ_ТОКЕН
```

Скрипт скачает бота в `/opt/market-bot`, впишет токен, один раз проверит страницу Маркета и запустит бота как сервис.
Потом напишите боту `/start`. Та же команда без токена — **обновление**: код заменится, `.env` и история цен останутся.

## Установка на сервер (Ubuntu, Нидерланды)

1. **Новый бот.** В [@BotFather](https://t.me/BotFather): `/newbot` → скопируйте токен.
   Нужен отдельный бот: токен SkinWatch не подойдёт, два процесса с одним токеном мешают друг другу.
2. **Node.js 22.** Если на сервере уже работает SkinWatch, этот шаг пропустите. Иначе:
   ```bash
   curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
   apt install -y nodejs
   node -v   # должно быть v22.13 или новее
   ```
3. **Скопируйте папку бота.** На GitHub откройте ветку `claude/adoring-euler-f2cetx` → Code → Download ZIP, распакуйте.
   Затем в PowerShell на своём компьютере:
   ```powershell
   scp -r "C:\путь\к\распакованному\market-bot" root@IP_СЕРВЕРА:/opt/
   ```
4. **Настройка** (на сервере, `ssh root@IP_СЕРВЕРА`):
   ```bash
   cd /opt/market-bot
   cp .env.example .env
   nano .env        # впишите BOT_TOKEN, сохраните: Ctrl+O, Enter, Ctrl+X
   ```
   Ваша ссылка `https://market.yandex.ru/cc/BPiBbv` уже стоит в `ITEM_URLS`: бот добавит её сам.
5. **Самопроверка.** Откроет ссылку так же, как бот, и покажет, что нашлось:
   ```bash
   npm run probe -- https://market.yandex.ru/cc/BPiBbv
   ```
   Должно быть `✅ Товар: …` и `Цена: …`. Если там `❌ Маркет показал капчу` — сначала раздел про капчу ниже.
   Если `страница открылась, но цену на ней найти не удалось` — пришлите файл `data/debug/probe.json`.
6. **Тесты** (по желанию): `npm test`.
7. **Запуск как сервис** — работает 24/7, сам поднимается после сбоя и перезагрузки:
   ```bash
   cp deploy/market-bot.service /etc/systemd/system/
   systemctl daemon-reload && systemctl enable --now market-bot
   journalctl -u market-bot -f        # логи (выход — Ctrl+C)
   ```
8. **Напишите боту `/start`.** Первый, кто это сделает, станет владельцем: только ему бот отвечает и шлёт уведомления.
   Можно задать владельца заранее: `ALLOWED_CHAT_IDS` в `.env` (свой id покажет команда `/id`).
9. **Резервная копия истории** раз в сутки: `crontab -e` и строка `10 4 * * * /opt/market-bot/deploy/backup.sh`.

**Обновление:** скопируйте новые папки `src` и `scripts` (не трогая `.env` и `data`) и выполните `systemctl restart market-bot`.
База обновится сама, история сохранится. Новые настройки из `.env.example` дописывать не обязательно — без них действуют значения по умолчанию.

## Если Маркет показывает капчу

Капча бывает разная: простая галочка «Я не робот» и задание с картинками.

1. **Поставьте браузер для бота** (Chromium, несколько сотен МБ на диске). Тогда при капче бот откроет страницу
   настоящим браузером и сам нажмёт галочку «Я не робот»:
   ```bash
   cd /opt/market-bot
   npm install playwright
   npx playwright install --with-deps chromium
   npm run probe -- https://market.yandex.ru/cc/BPiBbv --browser
   systemctl restart market-bot
   ```
   Cookie браузера сохраняются (`data/browser-state.json`), и при следующих визитах капчу обычно показывают реже.
   Задание с картинками бот не решает: в этом случае он пришлёт скриншот страницы и попробует в следующий раз.
2. **Если капча всё равно каждый день**, значит, Яндекс не доверяет IP сервера. Тогда остаётся одно из двух:
   - прокси с российским «домашним» IP (платный): `PROXY_URL=http://логин:пароль@адрес:порт` в `.env`.
     Прокси работает только через браузер (шаг 1), и с ним бот всегда ходит браузером;
   - запускать бота на домашнем компьютере, как SkinWatch в начале.

После ошибки бот пробует ещё раз через `RETRY_AFTER_MIN` минут (по умолчанию 120), если лимит в сутки позволяет.
Пока остаются попытки, он не пишет об ошибках. Сообщение приходит, только когда попыток на сегодня не осталось.

## Промокод

По умолчанию бот ищет промокод на 5% (`PROMO_PERCENT=5`). После каждой проверки в сообщении есть строка:

- `🎟 Есть промокод −5% (до 500 ₽), код STEAM5` и `💳 С промокодом: ≈ 1 032,65 ₽`;
- или `🎟 Промокода −5% на странице нет` (и какие другие промокоды есть, если есть).

Цена с промокодом берётся со страницы, если там написано «… ₽ с промокодом». Иначе бот считает её сам: цена − 5%,
но не больше потолка «до N ₽» (знак ≈). Потолок бот берёт со страницы, а если его там нет — из настройки.

Поменять, какой промокод искать, — команда `/promo` в боте: `5% до 500 ₽`, `5`, `любой` или `нет`.
Настройка из `/promo` важнее `.env`.

## Команды

| Команда | Что делает |
|---|---|
| ссылка на товар | добавить товар и сразу узнать цену (подойдёт и короткая ссылка «Поделиться») |
| `/list` | товары, последние цены и кнопки 🔄 Проверить · 📈 Динамика · 🎯 Цель · 🗑 Удалить |
| `/check` | проверить сейчас (считается в лимит на сутки) |
| `/history` | график, минимум/максимум, средние, день недели, таблица CSV |
| `/mode` | присылать цену после каждой проверки или только при изменениях |
| `/promo` | какой промокод искать: `5% до 500 ₽`, `5`, `любой`, `нет` |
| `/debug` | что бот увидел на странице: сводка, сама страница (.html), скриншот (если был браузер) |
| `/id` | ваш chat id |

В режиме «только при изменениях» бот пишет, если изменилась цена, наличие или продавец, появился или пропал промокод,
цена стала самой низкой за всё время или опустилась до вашей цели.

## Настройки (`.env`)

| Параметр | По умолчанию | Что значит |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather |
| `ALLOWED_CHAT_IDS` | пусто | кто владелец; пусто — первый, кто напишет `/start` |
| `ITEM_URLS` | ваша ссылка | товары, которые бот добавит при запуске |
| `CHECK_TIMES` | `12:00` | время проверок; две в день — `10:00,22:00` |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс для времени проверок и дат |
| `MAX_CHECKS_PER_DAY` | `2` | сколько раз в сутки можно открыть страницу одного товара (повторы и `/check` тоже считаются) |
| `RETRY_AFTER_MIN` | `120` | через сколько минут повторить неудачную проверку |
| `NOTIFY_MODE` | `always` | `always` — после каждой проверки, `change` — только при изменениях (меняется и в боте: `/mode`) |
| `PROMO_WATCH` | `1` | следить за промокодом (`0` — нет) |
| `PROMO_PERCENT` | `5` | какой промокод нужен, % (`0` — любой) |
| `PROMO_MAX_DISCOUNT` | пусто | потолок скидки «до N ₽», если на странице его нет |
| `BROWSER` | `auto` | `auto` — браузер, только если обычный запрос получил капчу; `always` — всегда браузер; `off` — никогда |
| `PROXY_URL` | пусто | прокси для браузера |

Одна попытка — это обычный запрос и, если он упёрся в капчу, ещё одна загрузка в браузере.

Если в `CHECK_TIMES` два времени, а лимит 2, то в день с ошибкой на повтор попыток не останется. Тогда поставьте
`MAX_CHECKS_PER_DAY=3` (если готовы к трём визитам) или оставьте как есть.

## Как бот выбирает цену

1. Короткая ссылка `market.yandex.ru/cc/…` ведёт на карточку товара. В адресе обычно есть номер предложения конкретного
   продавца (`do-waremd5=…`). Бот ищет на странице именно это предложение.
2. Если номера нет — берёт предложение этого товара, а если и его нет — цену из JSON-LD (основное предложение карточки).
3. Если на странице несколько чужих предложений и ни одно не совпало, бот всё равно покажет цену, но с пометкой
   «не уверен» и советом проверить `/debug`.

Каждая загрузка сохраняется в `data/debug/item-N.html` и `item-N.json` (последняя для каждого товара). Если Маркет
поменяет устройство страниц, по этим файлам видно, что исправлять.

## Файлы

```
src/index.js     запуск, расписание (раз в минуту смотрит, не пора ли проверять)
src/bot.js       команды, проверки, тексты уведомлений
src/market.js    загрузка страницы: обычный запрос с cookie, при капче — браузер Playwright
src/parse.js     разбор страницы: JSON-LD, patch-блоки, выбор предложения, признаки капчи
src/promo.js     поиск промокода на странице и цена с ним
src/stats.js     динамика: минимум, средние, день недели
src/chart.js     график PNG (свой растеризатор, без библиотек)
src/schedule.js  время по часовому поясу, лимит и повторы
scripts/probe.js самопроверка: npm run probe -- <ссылка>
data/            база (bot.db), cookie, отладочные копии страниц — не удаляйте, там история цен
```

## Если что-то не работает

- **«409: этот токен уже опрашивает другой процесс»** — бот запущен дважды (например, и на компьютере, и на сервере).
- **«Это личный бот»** — владелец уже назначен. Впишите свой id в `ALLOWED_CHAT_IDS` и перезапустите бота.
- **Цена не нашлась / не та** — `/debug` в боте или `npm run probe -- <ссылка>` на сервере; пришлите `probe.json`.
- **Капча каждый день** — раздел про капчу выше.
